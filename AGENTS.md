# Repository Guidelines

## Project Structure

- `src/index.ts` contains the MCP stdio server, `x_search` tool registration, xAI Responses API call, and response normalization.
- `scripts/smoke-test.ts` is an optional live MCP client check that calls the real xAI API.
- `docs/` contains installation and operator-facing documentation.
- `dist/` is generated by `npm run build`; update `src/` and rebuild instead of editing generated output.

## Build, Test, And Run

- Install dependencies with `npm install`.
- Build with `npm run build`.
- Run the built server with `npm start`.
- Run the TypeScript entrypoint during local development with `npm run dev`.
- Run `npm run smoke-test` only when `XAI_API_KEY` is available and a live xAI API call is intended.

## Coding Conventions

- Keep the server as an ESM NodeNext TypeScript project.
- Use the MCP SDK server APIs already in `src/index.ts` for tool registration and stdio transport.
- Use Zod schemas for MCP input and output shapes, and keep custom validation close to the schema it refines.
- Keep normalized tool responses shaped as both `structuredContent` and a text fallback.
- Log diagnostics to stderr with `console.error`; do not write arbitrary stdout output from the stdio MCP server.
- Do not add production dependencies, change the package entrypoint, or alter published files without confirming the need.

## xAI And Secrets

- Never commit `XAI_API_KEY` or other secrets.
- Prefer environment variables for `XAI_API_KEY`, `XAI_MODEL`, `XAI_BASE_URL`, and `XAI_TIMEOUT`.
- Treat changes to model defaults, API URLs, request payload shape, citation parsing, or timeout behavior as user-visible behavior changes.

## Verification Rules

- For TypeScript or runtime changes, run `npm run build`.
- For MCP startup changes, verify the server handshakes by connecting a local MCP client or listing tools; this does not require calling xAI.
- For docs-only changes, read back the changed doc and check the diff.
- If a live xAI check is needed, say explicitly that `npm run smoke-test` uses the configured API key and network.

## Agent Workflow

- Keep changes small and reviewable.
- Read `README.md`, `docs/INSTALL.md`, `package.json`, and nearby code before changing install or startup behavior.
- When troubleshooting Codex MCP startup, first check the configured command path and whether `dist/index.js` exists before investigating credentials.
- Use `$agents-md-maintainer` when revising this file.
